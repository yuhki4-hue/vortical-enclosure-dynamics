## 0. 判定規則と出典

一つの観察 `Scope`、受け手 `Recipient`、時間窓 `Window` を前もって宣言したと仮定する。これはどの支持物のどの役割を検査するかを指定する分析上の座標であって、固定された主体の存在を前提にしない。上流条件を固定した対の構成例を用い、ある橋の結果が出る例と出ない例を示す。対の差は橋の候補要因であり、現実での因果効果・必要十分条件を証明しない。

用語を四種に分ける。**D＝定義・役割判定**（語の適用条件）、**O＝独立に記録する観測条件**（結果ラベルより前に固定）、**M＝生成機構の仮説**（なぜ次の段へ進みうるか）、**R＝結果判定**（次段の成否）。D と R が同じ語になる場合は命名だけであり、M の証拠としない。下表の「可能条件」はあくまで指定模型内の候補で、知性一般の必要条件・十分条件ではない。「欠ける」はこの候補経路が止まるという意味で、全ての別経路の不可能性ではない。

## 1. 五段の分岐試験

### A. 現在の拘束・履歴 → 実現した F の進行

**D:** active F は、起きた `s₀→s₁` という生成遷移の記述である。全状態上の固定法則や、未実現の未来枝の集合ではない（D001、AR001）。旧 §3 の strict J は別模型の局所前提。**O:** 更新前の現在入力、浮上した履歴表現、環境との関係、後で確認できる遷移事象を分けて記録する。**M:** 圧縮・再浮上した履歴が現在環境と相互作用し、局所の方向を部分的に定めるという著者の構想（AR001）。**R:** 指定窓内に区別可能な実現遷移があったか。方向が読めることや「より良い」ことは別。

同じ入力と参照可能な履歴を与えた二つの思考例で、一方は現在の拘束下で新しい区別 `s₀→s₁` が生じ、他方は更新が生じないか、観察窓外に持ち越される。差として適用可能な拘束・タイミング・相互作用を置けるが、どれが現実の原因かは未同定。更新がないから知性がないとはしない。別経路には自発的な内部更新、外部からの刺激、異なる時間窓での変化が残る。

**先取り検査:** 「Fが進んだ状態」を事前入力に含めれば循環。観測前に候補入力と窓を固定し、更新事象の有無は後で判定する。候補識別点は、同一の現在入力でも履歴再浮上の条件が変わると遷移の経路・タイミングが変わるか。ただし event segmentation と同一条件の判定法は未所在。これは提案する検査方向であり、実行済み予測ではない。

### B. F の進行 → 痕跡の登録・保持

**D:** 生成履歴が生じたこと（AR002）と、後で追跡できる RetentionSupport に痕跡が登録されたことを分ける。後者は LR の名付け以前の結果である。**O:** 事前に指定した記録媒体・書込み経路、保存期間、support identity policy、追跡可能な痕跡を記録する。**M:** 更新過程が環境または系内の媒体へ痕跡を残し、その媒体が指定窓で失われない可能性。**R:** 同じ生成事象を、結果を見てから選んだ媒体でなく、指定supportから後に照合できるか。

対の例では、同じ `s₀→s₁` が実現する。一方は時点・内容の手掛かりを媒体へ登録し、指定窓まで保持する。他方は更新だけが起き、指定された受け手が再同定できるsupportを残さない。後者も「生成履歴が存在しない」ことにはならない。未観測の痕跡が別媒体にある可能性、系内記憶、環境の変形などの別経路を排除しない。

**先取り検査:** 後に LE と分類された媒体だけを選んで「Fはログを残した」と数えるのは不可。記録先と同一性規則を結果前に固定する。識別点は、同程度の更新で登録経路がある条件とない条件の、後の痕跡再同定率の差。ただし率の分母・検出法は未設計であり、提案を測定済み結果にしない。

### C. 登録された痕跡 → LR としての再参照

**D:** active LR は、指定scope/windowで原理的に再参照されうる登録・保持痕跡の**役割**である（JA §5:88）。実際に読み返されたこと、supportの存在、現在のaccessは別。LE'は同じsupportの一時的scaffold regimeで、LRから必ず進む段階ではない（AR003）。**O:** 登録時のsupport、連続性、受け手にとってのアクセス経路、再参照可能期間を、実際の再利用結果と別に記録する。**M:** 維持されたsupportに受け手からの参照経路が開き、過去痕跡が後の更新場面で浮上しうる。**R:** 指定窓でそのsupportを再参照できたか、実際に参照したかを二欄で判定する。

同じ痕跡が同じ媒体に登録された二例で、一方は受け手に読出し経路があり後で再参照できる。他方は媒体が残っていても受け手との経路が閉じる。後者はsupport lossではないし、別の受け手にはLR役割を持ちうる。別経路として内部記憶への再構成、複写物、他者による再投入が残る。ただし複写物を元supportと同一視するには独立の追跡根拠が要る。

**先取り検査:** 「読み返せたからLR」とするのは局所的な役割分類としては許容されるが、その同語反復で「LRを生む機構」を確認したとは言えない。実際の参照前に経路の存在・権限・保全を判定する必要がある。識別点は、同一痕跡で参照経路の有無を変えたとき、後の再参照事象と更新への再投入が分かれるか。再参照の抽出規則・同一性確認は未所在。

### D. LR の再参照 → LE の準安定な役割

**D:** active LE は指定scope/recipient/windowに対して追跡supportが担う準安定な保持役割。永久store、証明済みattractor、停止そのものではない（JA §5:143）。**O:** roleより前に support continuity、複数窓にまたがる保持、再参照経路、受け手の更新へ利用できる feedback path を定め、Unknownを許す。**M:** 再参照・共有・変形・外化を通じて保持の硬さ・再利用可能性が変わるという D009/AR003 の仮説。単一のpromotion則・閾値・単調な梯子ではない。**R:** 事前宣言された criterion のもとで、LE 役割が支持される／条件付き／非支持／Unknownを分ける。これは停止の成否を判定しない。

同じLR痕跡を実際に再参照した二例で、一方はsupportの連続性と後続窓の利用可能なfeedback経路が独立に残る。他方は一度読まれたがすぐ消える、あるいは再参照が現在の更新へ接続しない。前者はLE候補の条件が整い、後者は少なくとも同じcriterionでは支持不足になる。ただし前者もLEを現実に実証した例でなく、後者にも別supportへの移行、共有による保持、後日の再浮上の経路が残る。

**先取り検査:** 停止が起きたsupportをLEと呼んで、そのLEで停止を説明する循環を禁止する（JA §5:143、impl27 §5）。準安定性を「LEであること」と同義にせず、窓・許す変化・連続性・feedback pathの記録を先に置く。識別点は、LE候補と非候補の指定supportで、後続の再参照可能性・feedback availabilityが窓をまたいで違うか。ただし独立のcriterion/identity policyと実データは未所在。LE'を通らない保持経路も排除しない。

### E. LE 役割／E の利用 → 局所的停止効果

**D:** D003 の停止は foreground 履歴更新の減衰・局所residence・暫定的出力閉鎖を含み、global fixed pointではない。EはLEを置く・参照する・使うaction/reference effectというD008/AR006の方向であり、型と有効性は未完成。**O:** 停止をLE認定に使わず、更新頻度、保持期間、再開、背景変動を前もって別欄で観測する。support/recipientへの feedback path の有無と、実際の利用も分ける。**M:** 保持された履歴への参照が後続の判断に影響し、暫定的な停止・保留・再開を支えうる。影響の方向は固定しない。**R:** 指定窓で更新が減衰／局所保持／再開したか、support利用との時系列・比較根拠があるか。真理、適切さ、普遍的停止は別。

同じ事前LE役割評価を持つ二例で、一方は受け手がsupportを参照し局所的に出力を保持する。他方は同じsupportが利用可能でも参照しない、または参照後も更新を続ける。したがってLE役割は停止効果の十分条件ではない。逆にLE役割が認定されなくても、内部の局所保留、疲労、締切、外部応答、合意、遅延などで更新は止まりうる。いずれもLEの不必要性を一般証明したわけでなく、単一路線の必要性を先取りできないことを示す。

**先取り検査:** 「止まったからLEがあった」とする逆算、停止と同じeventをLE認定の唯一根拠にする二重計上は不可。識別点は、事前にrole評価されたsupportの利用有無と、局所停止・再開の時間差。条件が許すならsupportの利用可能性を変えた比較を考えられるが、選択バイアス、外部応答、課題終了規則、背景変動を区別しなければ因果効果は認定できない。新protocolや実測結果は作っていない。

## 2. 代替経路を残す依存図

```text
現在の履歴・環境 ──(仮説)──> 実現した更新 F
                                │
                         痕跡登録? ──> support持続? ──> LR再参照?
                                │                    ├──> 一時scaffold LE'（任意regime）
                                │                    └──> LE役割評価? ──> E利用? ──> 局所停止?
                                │
別経路: 内部の局所保留、別support、他者からの再投入、外部応答・合意・遅延、課題規則
```

矢印は確認済みの生成法則ではなく、比較する候補関係。疑問符は不成立・Unknown・別経路を許す。LE'は必須中間物でない。F の記述から LR 登録を自動導出せず、LE を最初から実体として前提しない。生成の可能性を開いたまま結果を保証しない構造である。

## 4. 監査結論と残る判断

現行本文と著者判断は、更新→記録→再参照→準安定な保持→停止支援という**可能な生成経路**を概念的に記述できる。成立例と不成立例が同じ上流条件の下で分かれるため、各接続は上流の定義から必然には従わない。一方、各段の独立したsupport・経路・時間窓・feedbackを検査対象として置けば、LEを無根拠な前提にする必要もない。これは模型の論理的余地に関する結論であり、現実の生成機構の確認ではない。

特に保留するもの: 新Jのstrict orderと旧定理3.1の移植、LR/LEの具体的identity criterion、LE形成・侵食の力学、Eの型と実効作用、停止の因果識別、AI単体／runtime／人間環境のsystem boundary、Φ二視点・μ/errorの新関係、VEDからの型付き導出。既存 D001–D018 と AR001–007 が示す方向は保持し、必要・十分・普遍的条件として昇格しない。

新たな人間判断をこの監査で確定しない。将来の研究では、G1–G4のどの橋から実際の事例・観測規則を作るか、どの系・時間窓を対象にするかが選択点となる。選ばれる前に例を「確認済み」にしない。本文修正の必要性は独立のsource reviewまで保留する。FIG009 の impl84 preflight HOLD は公開前確認の別件であり、本概念監査の成立条件ではない。
