# キャンペーン実装ツール（§12-2b・2c・3、2026-07-12）

実装前登録（ワーキングノートII §5.5.2・§2.2.1）に対応する3スクリプト。

## 1. phase_classifier_v1.py（2b：局所位相分類器）
- 入力：スナップショットTSV（列: epoch, V, 任意で b1H, b1S, label）。v24.2/v24.2e ログから該当列をエクスポートして渡す。
- `--scan` で (window_ratio, eps_ratio) 感度走査。**再現域（YES）の中央値を標準設定とする**（§5.5.2 検証条件）。
- 単一設定モードは `*_phases.tsv`（epoch, V, phase, subphase, label）を出力し、2c の入力となる。
- ε_h のスケール定数 0.25 は v24.2e の h U字振幅（0.7→0.5）由来の宣言値。走行ごとに調整しない。

## 2. band_fate_judge.py（2c：帯の運命判定）
- 入力：`*_phases.tsv`。(a)消滅／(b)定常化／(c)呼吸継続を機械判定。
- `--v-extinct` は**走行前に較正して固定**（min-npts が構造的に成立しなくなる V 水準）。
- **既知の境界挙動：** 合成単峰＋ノイズで switches=2 となり (c) が発火しうる。ノイズ由来の偽切替は ε を再現域内で上げるか、切替の最小持続長を追加して抑制する。判定が AMBIGUOUS の場合は事後選択せず走行を延長する。

## 3. growth_v24_3_rules.py（3：2×2規則分解）
- `growth v24 betti.py` のフォーク。**分配則と計器のみ変更**。4セルは §2.2.1 の配分式どおり。
- 実行例: `python growth_v24_3_rules.py 0.075 900 3,5,7,10,12,15 1200 cellA`
- 記録：n_dst、発火辺シェア、逆向き辺シェア（**反射は別カウント**——directed/cellB の dst=[(j,i)] 単独は構造的逆向き給餌と混同しない）、辺寿命（閉じた寿命のみ中央値に使用、打ち切りは censored として別掲）、スナップショットごとの V/E/b1H/b1S/label TSV（分類器互換）。
- SAT=YES のセルは主張から除外し NMAX を上げて再走行（§2.2.1 ヘッドルーム必須条項）。
- 交互作用判定は辺寿命中央値のみ：effect(片側)=med(A)−med(directed)、effect(両側)=med(sym)−med(B)。符号逆転または3倍差で交互作用あり。

## 初期観測（スモークテスト、100ep・N=300・1seed——統計主張ではない）
- cellA の発火辺シェア平均 ≈ 0.88：自己給餌許可時、配分のほぼ全量が発火辺自身へ戻る。希釈どころか**給餌の自己捕獲**が支配的である可能性。本走行での要注目点。

## 4. lattice_anchor_ext.py（d_cal アンカー4D拡張）
- panel() と同一の測定経路（全点対最短路→NN中央値単位→半径窓→log-log傾き）で参照格子アンカーを再生成。
- **監査で判明した三重感度**（2026-07-12、本ツールのスモークで発見）:
  1. **出自：既存アンカーは周期境界格子**（3D: 周期 9³=729 → 2.194 ≈ 既存2.204、4D: 周期 6⁴=1296 → 2.534 ≈ 既存2.526）。成長グラフは境界を持つため非周期の方が忠実だが、規約変更は過去の d_cal 全値を動かす。
  2. **サイズ依存が強い**：3D非周期 1.85(N=343)→2.12(N=2197)。アンカーは較正対象スナップの V に**サイズ整合**させる必要がある。
  3. **重み不均一で傾きが激増**：3D非周期 N=729 が単位重み1.968 → σ=0.5ジッタで**2.542**。実測系の W=−log(S) は不均一なので、単位重みアンカーとの比較は重み非整合。
- 帰結：directed 頑健BSW の外挿値3.43（b≈2.415）は、重み整合3Dアンカー（≈2.54）の**下**に来る可能性がある——「3.4次元」どころか3D整合の疑い。逆に周期・サイズ整合アンカーなら≈4.0。**規約（境界・サイズ・重み）を宣言してからでないと d_cal は次元主張に使えない。**
- 推奨手順：BSW窓スナップの −log(S) 辺重みをエクスポート → `--weights-from` で流し込み、非周期・サイズ整合・重み整合の4Dアンカー表を作る。

## 5. growth_campA_cycles.py ＋ campA_repair_turnover.py（キャンペーンA：cycle個体追跡）
- §7.6.1–7.6.4 の実装。セル：TD（三角挿入＝現行T1）／TL2（L=2 長周期挿入、主比較セル）。
- cycle同定＝誕生時代表元（原辺集合固定）。死亡＝**一度獲得したS支持の喪失**または端点死（新設辺はC=0から始まるため「獲得後喪失」の意味論が必須——獲得フラグで実装。初版は即死バグがあり修正済み）。
- 死亡帰属：new（新極の2辺）/path（既存最短路辺）を分離記録（§7.6.4のTL脆弱性チェック）。
- overlap graph は転置インデックスで毎スナップ構築、退化監視（density>0.5でフラグ）。
- alive集合を毎スナップ記録 → campA_repair_turnover.py が標準設定分類器出力と結合し、consolidation窓ごとの Jaccard（≥0.5 REPAIR / <0.25 TURNOVER / 中間 MIXED）を出す。閾値は走行前宣言。
- 実行例: `python growth_campA_cycles.py 0.075 900 5,7,10,15,21,33 2000 TL2`
  → 各seedで .tsv / _cycles.tsv / _alive.tsv の3ファイル。
- スモーク（300ep・s5、統計主張ではない）：TD 寿命中央値181・died_new 0.81 ↔ TL2 145・died_new 0.37。TL2のtl_fallback=3（初期の小グラフでのみ発生）。
- 本走行（900ep・6seed・NMAX=2000）：TD は cycle 寿命中央値 189.0、died_new 平均 0.763。TL2 は cycle 寿命中央値 146.5、died_new 平均 0.410。TD/TL2 の差は持続時間と死亡帰属で立つ。ただし標準分類器が検出した consolidation 窓は全12走行中2窓のみで、repair/turnover はどちらも MIXED（TD s33: J=0.409、TL2 s33: J=0.452）。900ep 本走行では repair/turnover 結論は保留。
